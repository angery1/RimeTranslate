# RimeTranslate v2.2.2

## 中文

这是一个以**翻译开关可靠性和请求状态恢复**为主的修复版本，同时替换了 README 中的两张实际运行截图。

### 修复

- 修复一种状态不同步问题：界面已经显示“翻译开”，但后台实际上没有发起新的翻译请求；
- Rime Lua 在 `ollama_translation` 开关变化时主动重置请求状态；
- 当响应文件被资源释放流程删除后，相同文本也可以重新发起翻译；
- Bridge 不再使用永久性的 `lastHandled` 文本去抑制重复请求，避免相同内容被错误判定为“已经处理”；
- `request.txt` 现在作为一个轻量的单槽请求队列：成功后才清除，临时的 Ollama 启动/请求错误会自动重试；
- 托盘“释放翻译资源”会同时清理 request / response / temp IPC 文件，下一次输入可以干净地重新建立请求；
- Bridge 启动时保留刚由 Rime 写入的 pending request，减少 Windows 登录/自启动时序造成的请求丢失。

### 如何判断故障发生在哪一层

如果输入法显示“翻译开”但候选没有翻译，可查看：

```powershell
Get-Content "$env:TEMP\rime_ollama_bridge\bridge.log" -Tail 30
Get-Content "$env:TEMP\rime_ollama_bridge\request.txt" -ErrorAction SilentlyContinue
Get-Content "$env:TEMP\rime_ollama_bridge\response.txt" -ErrorAction SilentlyContinue
```

“翻译开”只代表 Rime 的 `ollama_translation` option 已打开，并不等同于后台 Bridge、Ollama、模型调用和 F24 候选刷新链路全部健康。

## English

This patch focuses on **translation-toggle reliability and request-state recovery**, and replaces the two main README screenshots with newer real examples.

### Fixes

- Fixed a state desynchronization case where Rime showed “translation on” but no new backend request was actually issued;
- reset Lua request suppression whenever the `ollama_translation` option changes;
- allow the same text to be translated again after resource cleanup removes the previous response;
- remove the Bridge's persistent `lastHandled` text suppression that could incorrectly classify a valid request as already processed;
- use `request.txt` as a lightweight single-slot queue: clear it only after success and retry temporary Ollama/startup failures;
- resource cleanup now removes request, response, and temporary IPC files together;
- preserve a pending request written by Rime immediately before the Bridge starts, reducing login/startup race losses.
